## 빠른 답변

요리 퀘스트라인에서는 모든 식사, 재료 요청, 주방 이벤트, 하인 언급, 친밀도 변화를 한곳에 기록하세요. 퀘스트 UI나 반복 결과가 확인해 주기 전까지 레시피에 고정 능력치 조건이 있다고 가정하지 마세요.

## 요리 퀘스트라인 개요

| 루트 지점 | 추적할 것 |
|---|---|
| 범위 | 식사, 주방 요청, 재료 프롬프트, 하인 지원, 사기, 친밀도 단서 |
| 능력치 메모 | 행운, 매력, 재치를 낮은 확신도의 계획 단서로 다루기 |
| 가능성 있는 적합도 | 보이는 문구가 뒷받침한다면 사교적, 온화함, 신뢰성, 하인 대응 특성을 테스트할 가치가 있음 |
| 좋은 후보 | 요구 조건이 친절, 외교, 실용성을 가리킬 때 Angelica와 Gwendan을 비교하기 |
| 주요 위험 | 반복 검증 전에 분위기 이벤트를 확정된 시스템으로 바꾸는 것 |

## 단계별 진행

1. 이벤트 이름, 재료, 배정 기사, 보이는 요구 조건, 결과 열을 가진 요리 기록을 시작하세요.
2. 하인, 주방, 사기, 회복, 친밀도 관련 문구를 나중에 비교할 수 있을 만큼 정확히 복사하세요.
3. 보이는 요구 조건을 먼저 기준으로 배정하고, 특성 가설은 퀘스트 문구가 뒷받침할 때만 사용하세요.
4. 결과가 충성도, 친밀도, 회복, 자원, 이후 주방 선택지를 바꾸는지 기록하세요.
5. 놀라운 결과는 확정 요리 시스템이라고 부르기 전에 다른 기사로 다시 테스트하세요.
6. 이름 있는 레시피나 반복 주방 이벤트는 요구 조건이 안정되면 하위 퀘스트 페이지로 분리하세요.

## 확인할 사항

| 확인할 주장 | 검증 메모 |
|---|---|
| 레시피 요구 조건 | 각 이벤트가 능력치, 특성, 재료, 루트 상태 중 무엇을 사용하는지 확인하기 |
| 하인 효과 | 주방 이벤트가 하인을 해금하거나, 서비스를 개선하거나, 탑 시스템을 바꾸는지 추적하기 |
| 친밀도 영향 | 식사가 항상 긍정적이라고 가정하지 말고 정확한 친밀도 또는 충성도 변화를 기록하기 |
| 회복 시스템 | 요리가 부상, 피로, 사기에 영향을 주는지, 아니면 단순한 분위기 문구인지 확인하기 |
| 반복 이벤트 | 1회성 장면과 반복 가능한 요리 임무를 분리하기 |

## FAQ

### 요리가 친밀도를 올리나요?

가능성은 있지만, 루트 메모가 요리 이벤트와 연결된 명확한 친밀도 또는 충성도 변화를 보여 줄 때까지는 미확정으로 다루세요.

### 요리 퀘스트는 누가 맡아야 하나요?

보이는 요구 조건에 맞는 기사를 사용하세요. 문구가 친절, 외교, 하인 상호작용을 암시한다면 Angelica나 Gwendan은 사용 가능할 때 유용한 테스트 후보가 될 수 있습니다.

### 모든 레시피가 별도 페이지가 되어야 하나요?

레시피 이름, 요구 조건, 결과를 명확히 문서화할 수 있을 때만 별도 페이지로 만드세요. 그 전까지는 이 퀘스트라인 페이지 안에 레시피 메모를 보관하세요.
