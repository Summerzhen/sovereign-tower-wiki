## 빠른 답변

하인과 Intendant 루트는 탑 내부 관리를 추적하는 데 사용하세요. 하인 이름, Intendant 대화, 부속 시설 언급, 자원 효과, 퀘스트 접근이나 충성도 또는 이후 위험을 바꾸는 행정 선택을 기록합니다.

## 루트 개요

| 루트 포인트 | 작업 계획 |
|---|---|
| 주요 목표 | 탑 운영 선택과 그것이 하인, 부속 시설, 자원에 미치는 영향 매핑 |
| 계획용 능력치 | Wit과 Charisma는 행정과 설득을 위한 계획 메모이며 불확실성은 능력치와 따로 기록 |
| 추천 기준점 | 가능할 때 Gwendan, Angelica, Dullahan을 비교 대상으로 사용 |
| 좋은 특성 | 문제 해결, 외교, 루트 지식, 신중한 판단 |
| 주요 위험 | 테스트 전의 하인 분위기 대사를 기계적 해금으로 확정하는 것 |

## 단계 / 루트 적합도

1. 등장하는 하인, Intendant 장면, 부속 시설 언급, 탑 운영 문제를 각각 기록합니다.
2. 선택하기 전에 현재 자원, 세력 상태, 명단 부상, 이용 가능한 부속 시설을 적습니다.
3. 표시 요구 조건이나 장면 논리에 따라 기사를 배정한 뒤, 특성이 신뢰, 규율, 회복, 접근을 바꾸는지 기록합니다.
4. 행정 분위기 텍스트와 새로운 직책, 자원 변화, 선택지 해금 같은 확인된 시스템 변화를 분리합니다.
5. 불명확한 선택 주변에서 되감기 테스트를 수행해 다른 기사나 판결이 같은 하인 결과를 바꾸는지 확인합니다.
6. 하인 또는 Intendant 이벤트의 분기가 안정되면 별도 퀘스트 기록으로 분리합니다.

## 현재 빌드 확인 사항

| 확인할 주장 | 검증 메모 |
|---|---|
| 하인 이름 | 개별 페이지를 만들기 전에 게임 내 텍스트에서 정확한 이름과 역할 확인 |
| Intendant 기능 | Intendant가 자원, 루트 접근, 탑 질서를 바꾸는지, 아니면 대사만 바꾸는지 추적 |
| 부속 시설 지원 | 선택이 forge, alchemy, garden, quarters 같은 시스템을 해금, 개선, 언급하는지 확인 |
| 기사 영향 | 특성이 하인 신뢰나 행정 결과에 영향을 주는지 테스트 |
| 장기 비용 | 지연된 충성도, 세력, 자원, 루트 결과를 따로 기록 |

## FAQ

### Intendant 루트는 전투 루트인가요?

아니요. 특정 이벤트가 전투나 퀘스트 배정 요구 조건을 보여주지 않는 한 탑 관리 루트로 다루세요.

### 하인 선택이 부속 시설을 해금할 수 있나요?

가능성은 있지만, 선택이 안정적으로 시스템 변화를 만들기 전까지 해금 표현은 신중하게 유지해야 합니다.

### 하인 이벤트에는 어떤 능력치가 중요한가요?

Wit과 Charisma는 유용한 계획 범주입니다. 현재 빌드가 능력치 라벨을 보여주지 않으면 불확실한 결과는 루트 메모로 다루세요.

### 하인 이벤트는 언제 자체 페이지가 필요하나요?

이벤트에 안정적인 이름, 명확한 요구 조건, 알려진 결과, 반복 가능한 루트 결과가 있을 때 전용 페이지를 만드세요.
