## 快速解答

圆桌是你将觐见请求转化为骑士任务分配的地方。在派出骑士之前，需对比可见的任务需求、所需属性、特质契合度、护甲状态、忠诚度、亲和力，以及该骑士是否还需要执行其他有截止期限的任务。

使用[任务数据库](/quests)进行任务筛选，使用[骑士数据库](/knights)查看属性、特质、餐食、进化及最佳分配方案。

## 分配检查清单

| 检查项 | 重要原因 |
|---|---|
| 所需属性 | 最稳妥的匹配从可见的任务需求开始 |
| 特质与隐藏特质 | 特质可以改善、扭曲或破坏预期结果 |
| 护甲与健康风险 | 即使匹配良好，带伤出战仍可能死亡 |
| 忠诚度/亲和力 | 心怀不满的骑士可能拒绝命令、离队或触发意外分支风险 |
| 可用性 | 长时间任务会让骑士无法参与其他紧急分配 |
| 路线影响 | 部分任务会影响招募、结局、阵营或后续对话 |

## 圆桌工作流程

1. 完成晨间觐见，列出所有已接受的问题。
2. 按截止期限、危险度和路线重要性对任务排序。
3. 优先分配必须成功的任务，再处理可选差事。
4. 用装备或药剂弥补单项短板，而非弥补整体不匹配。
5. 留出弹性空间，应对归队骑士、修理和后续觐见。
6. 在回溯或进入下一循环前记录结果。

## 角色覆盖表

| 任务需求 | 适用骑士画像 |
|---|---|
| 战斗/狩猎 | 力量、敏捷、护甲，且背叛风险低 |
| 外交 | 魅力、稳定忠诚度及社交特质 |
| 调查 | 智力、运气，以及与观察或秘密相关的特质 |
| 魔法/异怪事件 | 魔法、超自然耐受性，且恐惧/敌对风险低 |
| 治安路线 | 魅力或力量，配合阵营兼容的选择 |

## 常见圆桌失误

| 失误 | 更好的习惯 |
|---|---|
| 只选属性最高的 | 检查厌恶的任务类型和隐藏特质风险 |
| 仍派受损骑士出战 | 修理护甲或选择风险更低的任务 |
| 每个循环填满所有骑士槽位 | 尽量为紧急后续任务留出空位 |
| 忽视轻微失败 | 轻微失败日后可能成为路线或结局证据 |
| 不做记录就回溯 | 在改变时间线前先记下失败的任务分配 |

## 常见问题

### 圆桌只看属性吗？

不是。属性最重要，但特质、护甲、亲和力、忠诚度、路线状态和装备都能改变最终结果。

### 是否应该总是派出最强骑士？

不一定。将最强匹配留给截止期限最紧、死亡风险最高或路线影响最大的任务。

### 圆桌选择会影响结局吗？

会。任务结果可以改变阵营状态、招募、恋爱及后期路线标记，因此重要分配应当记录在案。
